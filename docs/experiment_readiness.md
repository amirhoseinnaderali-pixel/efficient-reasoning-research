## Benchmark

EXP-001 uses `humaneval-stratified-100-v1`, locked by `benchmarks/manifests/exp001_v1.json`.

The manifest locks 100 unique HumanEval task IDs, category counts, assertion counts, canonical task/test hashes, the upstream HumanEval source commit, and the canonical archive SHA-256. The repository does not modify the source benchmark labels or oracle tests.

The model-facing prompt is a deterministic derived view: `strip_doctest_examples_v1` removes interactive `>>>` input/output examples from the prompt to prevent answer leakage. The canonical test source remains hash-locked. The hidden suite is never passed to a reasoning strategy.

The materialized benchmark is intentionally generated by `scripts/materialize_exp001_benchmark.py` from the pinned upstream commit. Real EXP-001 execution refuses to proceed if materialization is missing or fails the manifest hashes.

## Execution environment

The execution image is pinned to:

`python:3.12-slim-bookworm@sha256:392307d22300de8b5986851a12d9176dfc0fc073e65bf6523ebd7dcbeb23564e`

The sandbox policy is `docker_strict_v1`: network disabled, explicit CPU/memory/PID limits, read-only root filesystem, isolated no-exec `/tmp`, dropped capabilities, no-new-privileges, timeout, and subprocess cleanup.

## Fixed compute budget

Every strategy receives the same hard upper budget:

- 8 model calls
- 9,600 generated tokens
- 40,000 input tokens
- 300 seconds strategy wall-clock
- 12 execution steps
- 8 candidates maximum

Calls, input tokens, output tokens, model latency, execution latency, graph latency, wall-clock time, candidate count, execution steps, and cost proxy remain separate accounting dimensions.
